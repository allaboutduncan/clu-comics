{# Confirmation for the destructive library-wide thumbnail rebuild. Included by both config.html and collection.html. Regenerating rebuilds every folder's art from scratch, which means deleting whatever image is there now -- including art the user uploaded by hand, since nothing on disk distinguishes a generated folder.png from an uploaded one. That is why this is a modal and not a toast, and why it never uses confirm(). #}
Regenerate All Thumbnails

Rebuild folder cover art for every folder in your library using the current thumbnail style.

Existing folder images will be deleted. Every folder.png, folder.jpg, folder.jpeg, folder.gif and folder.webp inside it is removed and replaced — including cover art you uploaded yourself. This cannot be undone.
{# The one thing this action does NOT touch. Worth its own callout: a publisher folder's image is usually hand-picked, and without saying so the danger notice above reads as though it goes too. #}
Your library root keeps its own thumbnail — only the folders nested inside it are rebuilt.

Pinned covers are kept: a folder with a pinned issue keeps using it. On a large library this runs in the background and can take a while.
